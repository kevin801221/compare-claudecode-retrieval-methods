# Wiki 目錄

## 概念（concepts）
- [[concepts/agent-sdk-agent-loop]] — Agent SDK 執行與 Claude Code 相同的自主代理迴圈（agent loop）：接收提示詞、由 Claude 評估並呼叫工具、收集工具執行結果回饋給 Claude，並不斷重複直到產生不含工具呼叫的最終文字回應。關鍵詞：Agent Loop 運作原理、代理迴圈、Turn 生命週期
- [[concepts/agent-sdk-file-checkpointing]] — File Checkpointing（檔案檢查點）會在代理工作階段期間追蹤透過 `Write`、`Edit` 與 `NotebookEdit` 工具所做的檔案修改，並在修改前建立檔案備份，讓開發者能將磁碟上的檔案還原（Rewind）至先前任一提示詞回合（Turn）開始時的狀態。關鍵詞：檔案檢查點、檔案還原、Rewind Files
- [[concepts/agent-sdk-hooks]] — Agent SDK 的 Hooks 機制讓開發者在代理執行的關鍵生命週期節點（如工具呼叫前後、提示詞送出、Subagent 啟動與結束、上下文壓縮前、工作階段啟停等）註冊回呼函式或載入設定檔 shell 指令，以阻擋危險操作、修改工具輸入或輸出、注入額外上下文、記錄稽核軌跡或發送外部通知。關鍵詞：Agent SDK Hooks 攔截與控制、生命週期回呼、HookMatcher
- [[concepts/agent-sdk-mcp]] — Agent SDK 支援透過 Model Context Protocol (MCP) 連接本地 `stdio` 子處理程序、遠端 `http` / `sse` 伺服器以及處理程序內的 SDK MCP 伺服器，並可透過程式碼 `mcpServers` / `mcp_servers` 或專案根目錄 `.mcp.json` 設定。關鍵詞：Agent SDK MCP 伺服器與工具搜尋、Model Context Protocol、mcpServers
- [[concepts/agent-sdk-permissions]] — Claude Agent SDK 透過六階段權限評估流程（Hooks → Deny rules → Ask rules → Permission mode → Allow rules → `canUseTool` callback）控管所有工具呼叫。關鍵詞：Agent SDK 權限管理、權限評估順序、Permission Modes
- [[concepts/agent-sdk-sessions]] — Agent SDK 的工作階段（Session）會自動將代理人的對話歷史（包含使用者提示詞、每次工具呼叫、每個工具執行結果與每次回應）寫入磁碟的 JSONL 紀錄檔（Transcript），讓後續執行能帶著完整脈絡（已讀取的檔案、已執行的分析與決策）繼續、恢復或分叉對話。關鍵詞：工作階段與對話持久化、Sessions、Session Storage
- [[concepts/agent-sdk-skills-and-plugins]] — Agent SDK 支援透過檔案系統探索並按需載入 `SKILL.md` 技能、在提示詞中以 `/<name>` 派發內建或自訂斜線指令（如 `/compact`、`/clear`），以及透過 `plugins` 選項從本地目錄載入整合了 skills、agents、hooks 與 MCP 伺服器的外掛套件（並自動套用 `plugin-name:skill-name` 命名空間）。關鍵詞：Agent SDK 技能、指令與外掛、Skills
- [[concepts/agent-sdk-streaming]] — Claude Agent SDK 的串流機制分為「輸出串流（Output Streaming）」與「輸入模式（Input Modes）」兩大面向。關鍵詞：即時串流輸出、串流輸入模式、單一訊息模式
- [[concepts/agent-sdk-structured-outputs]] — Structured Outputs（結構化輸出）允許開發者透過 JSON Schema（可直接手寫，或由 TypeScript 的 Zod、Python 的 Pydantic 產生）定義代理人最終必須回傳的資料結構。關鍵詞：結構化輸出、JSON Schema 輸出、Structured Outputs
- [[concepts/agent-sdk-subagents]] — Subagents 是由主代理透過 `Agent` 工具衍生的獨立代理實例，具備獨立上下文視窗、平行執行能力、專屬系統提示詞與受限工具集。關鍵詞：Agent SDK 子代理、Subagents、AgentDefinition
- [[concepts/claude-agent-sdk-overview]] — Claude Agent SDK 將驅動 Claude Code 的工具、agent loop 與上下文管理封裝為 Python 與 TypeScript 函式庫，供開發者在自有處理程序中建構與執行 AI 代理。關鍵詞：Claude Agent SDK 概覽與設定、Agent SDK 架構與功能載入、Options
- [[concepts/deepagents-backends-and-sandboxes]] — Deep Agents 透過可插拔的後端協定（`BackendProtocol` / `BackendProtocolV2`）為代理提供虛擬檔案系統工具（`ls`、`read_file`、`write_file`、`edit_file`、`delete`、`glob`、`grep`），並在實作 `SandboxBackendProtocol`（或 `LocalShellBackend`）時額外啟用 `execute` shell 工具。關鍵詞：檔案系統後端與沙盒、`BackendProtocol`、`SandboxBackendProtocol`
- [[concepts/deepagents-code-approval-and-hooks]] — Deep Agents Code（`dcode`）提供三層安全與執行控制機制：其一為人機迴路核准模式（Approval modes，包含預設的 `Manual`、結合窄確定性規則與 LLM 分類器的 `Auto`，以及無須審查的 `YOLO`）；其二為生命週期命令掛鉤（Hooks，透過 `~/.deepagents/hooks.json`、`.deepagents/hooks.json` 或外掛程式攔截 `PreToolUse`、`PostToolUse`、`PermissionRequest`、`Stop` 等 11 種事件，並以退出碼 `0` 或 `2` 及 JSON stdout 控制允許、拒絕或注入上下文）；其三為遠端沙盒（Remote sandboxes，支援 `langsmith`、`agentcore`、`daytona`、`modal`、`runloop`、`vercel`、第三方 `e2b` 及 `config.toml` 自訂沙盒供應商，將代理工具呼叫導向遠端環境執行）。關鍵詞：Deep Agents Code 核准模式與掛鉤、Manual/Auto/YOLO 核准模式、hooks.json 生命週期掛鉤
- [[concepts/deepagents-code-extensibility]] — Deep Agents Code（`dcode`）提供六大模組化擴充與品質控管機制：透過 Model Context Protocol（`.mcp.json`）整合外部 stdio/SSE/HTTP 工具與 OAuth 驗證；透過自動記憶（`memories/*.md`）、`AGENTS.md` 與符合 Agent Skills 規範的 `SKILL.md` 管理長期偏好與領域工作流；透過 Markdown frontmatter 定義自訂同步子代理（subagents）或以程式碼直譯器執行 `task()` 動態子代理；透過相容 Claude/Codex 規範的外掛與市集（Plugins & Marketplaces）打包發佈功能；透過實驗性 `ExtensionAPI`（Python extensions）直接向代理伺服器註冊工具、LangChain 中介軟體與虛擬儲存路由；以及透過目標（`/goal`）與評分標準（`/rubric`）建立自動化品質驗收迴圈。關鍵詞：Deep Agents Code 擴充機制、MCP 工具與信任模型、AGENTS.md 記憶與技能
- [[concepts/deepagents-context-engineering]] — Deep Agents 的上下文工程（Context Engineering）涵蓋五種上下文機制：啟動時的靜態輸入上下文（Input context）、單次執行的執行階段上下文（Runtime context）、自動與按需的上下文壓縮（Context compression，包含卸載與摘要）、透過子代理進行的上下文隔離（Context isolation），以及跨對話持久化的長期記憶（Long-term memory）。關鍵詞：上下文工程、Context Engineering、`SummarizationMiddleware`
- [[concepts/deepagents-harness-and-multimodal]] — 本頁彙整 Deep Agents 的四大進階執行期與配置機制：**Profiles**（透過 `HarnessProfile` / `HarnessProfileOptions` 與 Python 專屬的 `ProviderProfile` 封裝針對特定模型或供應商的提示詞、工具與 Middleware 預設值）、**Multimodality**（透過標準內容區塊與內建 `read_file` 工具處理圖片、音訊、影片與文件，以及上下文壓縮對多模態內容的影響）、**Grading Rubrics**（透過 `RubricMiddleware` 在執行期實作 LLM-as-a-judge 自我評估與迭代修正迴圈），以及 **Interpreters**（基於 WebAssembly 隔離的 QuickJS 記憶體內 JavaScript 執行環境 `eval`，支援 Programmatic Tool Calling (PTC) 與動態子代理 `task()` 調度）。關鍵詞：Harness Profiles、Provider Profiles、多模態輸入輸出
- [[concepts/deepagents-human-in-the-loop]] — Deep Agents 透過整合 LangGraph 的 interrupt 機制與 `HumanInTheLoopMiddleware`，讓代理在執行敏感工具或寫入受保護的檔案路徑前暫停並交由人類審批。關鍵詞：人類介入審批、Human-in-the-loop、HITL
- [[concepts/deepagents-memory-and-skills]] — Deep Agents 以虛擬檔案系統為基礎實現一等公民的長期記憶（Memory）與技能（Skills）。關鍵詞：長期記憶與技能、Memory、Skills
- [[concepts/deepagents-overview]] — Deep Agents 是建構於 LangChain 與 LangGraph 之上的代理測試與執行框架（agent harness），專為複雜、多步驟的任務設計，提供任務規劃、虛擬檔案系統、子代理（subagent）委派與長期記憶。關鍵詞：Deep Agents 總覽、Deep Agents 架構、Agent Harness
- [[concepts/deepagents-protocols-and-integrations]] — 本頁說明 Deep Agents 與外部系統通訊的標準協定與發行紀錄：**ACP（Agent Client Protocol）** 透過 `deepagents-acp` 套件以 stdio 模式將代理連接至程式碼編輯器與 IDE（如 Zed、JetBrains IDEs、VS Code、Neovim 與 Toad）；**AG-UI（Agent User Interaction Protocol）** 透過 `@ag-ui/langgraph` 的 `LangGraphAgent` 將 LangGraph 伺服器上的代理轉換為型別化事件串流以驅動前端介面；**A2A（Agent2Agent）** 提供跨代理間的通訊整合；並收錄 Python 與 JavaScript SDK 的官方 Changelog 參照。關鍵詞：Agent Client Protocol、ACP、deepagents-acp
- [[concepts/deepagents-streaming-and-fault-tolerance]] — Deep Agents 建構於 LangGraph 串流與中斷基礎設施之上，支援透過傳統 `subgraphs=True` 與命名空間（namespaces）串流子代理進度，並在 v0.6 引入強型別投影的 Event Streaming API（`stream_events` / `streamEvents` 與 `stream.subagents`），讓開發者能獨立消費協調器與各層子代理的訊息、工具呼叫與狀態。關鍵詞：串流與容錯機制、Streaming、Event Streaming
- [[concepts/deepagents-subagents]] — Deep Agents 支援透過子代理（subagents）進行上下文隔離（context quarantine）與任務委派，避免多步驟任務的中間工具結果塞滿主代理的上下文視窗。關鍵詞：子代理、Subagents、`SubAgent`
- [[concepts/langchain-agents-and-runtime]] — LangChain 的代理（Agent）是一個在迴圈中持續呼叫工具直到完成任務的模型，其外圍由提示詞、工具與中介軟體（middleware）構成的 Harness 加以塑形。關鍵詞：LangChain 代理與執行期環境、`create_agent`、`createAgent`
- [[concepts/langchain-human-in-the-loop-and-guardrails]] — LangChain 透過 `HumanInTheLoopMiddleware`（JS：`humanInTheLoopMiddleware`）與護欄（Guardrails）機制，為代理工具呼叫與內容輸入/輸出提供安全性與合規控制。關鍵詞：人機迴圈與護欄、人工審核與安全防護、HITL
- [[concepts/langchain-mcp]] — LangChain 透過 `MCPAdapter` 將採用 Model Context Protocol（MCP）的本地或遠端伺服器工具整合進代理（`create_agent` / `createAgent`）。關鍵詞：模型上下文協定整合、MCP 伺服器連接、Model Context Protocol
- [[concepts/langchain-memory-and-context-engineering]] — LangChain 將代理（Agent）的記憶分為單一對話執行緒（Thread）內的短期記憶（Short-term memory，透過 `checkpointer` 與 `AgentState` 管理）以及跨對話執行緒與工作階段的長期記憶（Long-term memory，透過 LangGraph `store` 以 `namespace` 與 `key` 儲存 JSON 文件）。關鍵詞：短期記憶與長期記憶、上下文工程、Short-term Memory
- [[concepts/langchain-middleware]] — LangChain 的中介軟體（Middleware）提供在代理執行迴圈（Agent Loop）各個階段攔截、轉換與控制資料流的能力，可用於日誌追蹤、動態提示詞與工具篩選、重試與降級（Fallback）、速率限制、護欄（Guardrails）及 PII 偵測。關鍵詞：中介軟體架構、自訂中介軟體、Agent Middleware
- [[concepts/langchain-multi-agent-handoffs]] — 在 **Handoffs（移交）** 架構（亦稱為 **State Machine Pattern**）中，代理的行為會根據跨輪次持久化的狀態變數（如 `current_step` 或 `active_agent`）動態改變。關鍵詞：代理移交與狀態機模式、Handoffs Pattern、State Machine Pattern
- [[concepts/langchain-multi-agent-overview]] — LangChain 的多代理（Multi-agent）系統透過協調多個專業化元件來處理複雜的工作流程，核心目的在於解決上下文管理（Context management）、分散式開發（Distributed development）與平行化執行（Parallelization）三大需求。關鍵詞：多代理架構總覽與自訂工作流、Multi-Agent Patterns、Custom Workflow
- [[concepts/langchain-multi-agent-router-and-skills]] — **Router（路由器）** 與 **Skills（技能）** 是兩種互補的多領域知識管理架構：**Router** 透過專用分類步驟將輸入拆解為針對不同垂直領域（Verticals）的子問題，利用 LangGraph `Command`（單一代理）或 `Send` API（多代理平行扇出）分發至獨立代理，並透過狀態 Reducer 收集結果後綜合（Synthesize）為單一答案；**Skills** 則採用漸進式揭露（Progressive disclosure），讓單一代理在系統提示詞中僅看見輕量級技能描述，並在需要時透過 `load_skill` 工具按需載入完整的資料庫 Schema、業務邏輯或參考資源。關鍵詞：路由器與技能模式、Router Pattern、Skills Pattern
- [[concepts/langchain-multi-agent-subagents]] — 在 **Subagents（子代理）** 架構中，一個中央主代理（Main agent，常稱為 **Supervisor**）透過將子代理包裝為工具（Tools）進行調用與協調。關鍵詞：子代理與監督者模式、Subagents Pattern、Supervisor Architecture
- [[concepts/langchain-overview-and-architecture]] — LangChain 以「**Agent = Model + Harness**」為核心概念，提供精簡且高度可配置的代理框架（Harness）`create_agent`（Python）與 `createAgent`（JavaScript/TypeScript），讓開發者透過模型、提示詞（prompt）、工具（tools）與中介軟體（middleware）組合出符合需求的 AI 代理。關鍵詞：LangChain 概覽與架構、LangChain 設計哲學、LangChain 安裝與快速入門
- [[concepts/langchain-streaming]] — LangChain 提供兩套互補的串流介面：其一是基於底層 LangGraph Pregel 的 `stream()` / `astream()`（支援 `updates`、`messages`、`custom` 等 `stream_mode` 以及統一結構的 `version="v2"` `StreamPart` 格式）；其二是 LangChain v1.3 引入、推薦新應用程式採用的高階型別化投影 API **Event Streaming**（透過 `stream_events(..., version="v3")` / `streamEvents(..., { version: "v3" })` 提供 `.messages`、`.tool_calls` / `.toolCalls`、`.values`、`.subagents`、`.subgraphs`、`.extensions` 與 `.output` 等獨立串流投影）。關鍵詞：LangChain 串流與事件串流、`stream()`、`astream()`
- [[concepts/langchain-structured-output]] — 結構化輸出（Structured output）讓 LangChain 代理能以可預測、經過驗證的格式（如 Pydantic 模型、Dataclass、TypedDict、Zod schema、Standard Schema 或 JSON Schema）回傳資料，並自動存入代理最終狀態的 `structured_response`（Python）或 `structuredResponse`（JavaScript/TypeScript）欄位中。關鍵詞：LangChain 結構化輸出、`response_format`、`responseFormat`
- [[concepts/langgraph-control-flow-send-and-command]] — LangGraph 的控制流決定工作如何在節點之間傳遞，支援序列（sequences）、平行分支（parallel branches）、條件分支（conditional branching）、迴圈（loops）、Map-Reduce 動態展開（`Send`）以及將狀態更新與路由合而為一的 `Command`。關鍵詞：LangGraph 控制流、Edges 與 Conditional Edges、Parallel Branches
- [[concepts/langgraph-functional-api-and-pregel]] — LangGraph 提供兩大高階 API——Graph API（`StateGraph`）與 Functional API（`@entrypoint`／`@task`），兩者在編譯或建立後皆會產生底層的 `Pregel` 執行期實例。關鍵詞：Functional API 與 Pregel 執行期、@entrypoint 與 @task、Bulk Synchronous Parallel (BSP)
- [[concepts/langgraph-graph-api-state-and-nodes]] — LangGraph 的 Graph API 將代理工作流建模為由共享狀態（`State`）、節點（`Nodes`）與邊（`Edges`）組成的圖形，並以類似 Google Pregel 的離散超步（super-steps）訊息傳遞機制執行。關鍵詞：Graph API 狀態與節點配置、StateGraph、Reducers
- [[concepts/langgraph-interrupts-and-time-travel]] — LangGraph 透過 Checkpointer 支援兩項核心控制流機制：**Interrupts（中斷）** 允許在節點或工具函式內部任意位置呼叫 `interrupt()` 動態暫停圖執行、將 JSON 可序列化的負載回傳給呼叫端，並於收到 `Command(resume=...)` 後從該節點開頭重新執行以完成 Human-in-the-loop（HITL）審批、編輯與輸入驗證；**Time Travel（時光旅行）** 則允許透過 `get_state_history` 檢索歷史 Checkpoint，並以 `invoke(None, snapshot.config)` 重播（Replay）後續節點，或透過 `update_state` 建立狀態修改後的執行分叉（Fork）。關鍵詞：中斷與時光旅行、Human-in-the-loop、HITL
- [[concepts/langgraph-memory-and-stores]] — LangGraph 將代理記憶分為兩大層級：**短期記憶（Short-term memory）** 透過 Checkpointer 將狀態持久化於單一 `thread_id` 內以支援多輪對話，並透過 `trim_messages`、`RemoveMessage` 與 `SummarizationNode` 控制上下文視窗長度；**長期記憶（Long-term memory）** 則透過實作 `BaseStore` 介面的 Store（如 `InMemoryStore`、`PostgresStore`、`MongoDBStore`、`RedisStore`、`OracleStore`）將跨執行緒的使用者偏好或知識依 `namespace` 與 `key` 儲存為 JSON 項目（`Item`），並支援基於 Embedding 的語意搜尋（Semantic Search）。關鍵詞：記憶與儲存、長期記憶、短期記憶
- [[concepts/langgraph-overview-and-workflows]] — LangGraph 是針對長時間執行、具狀態代理程式（stateful agents）的低階編排框架與執行期（runtime），透過共享狀態（state）、節點（nodes）與邊（edges）定義工作流，並可在同一張圖中混用確定性步驟與 LLM 驅動步驟。關鍵詞：LangGraph 概覽與工作流模式、Graph API 設計流程、Workflows 與 Agents
- [[concepts/langgraph-persistence-and-checkpointers]] — LangGraph 的持久化層（Persistence）由兩個互補系統組成：**Checkpointers** 負責在每個 super-step 邊界將單一執行緒（Thread）的圖狀態儲存為檢查點（Checkpoint），提供對話延續、Human-in-the-loop 中斷恢復、時光旅行（Time Travel）與容錯恢復（Fault Tolerance）等短期記憶功能；**Stores** 則負責儲存圖狀態以外的跨執行緒鍵值資料（長期記憶）。關鍵詞：持久化與檢查點、Checkpointer、狀態快照
- [[concepts/langgraph-streaming]] — LangGraph 提供兩層串流架構：底層的 **Streaming（串流模式 API）** 直接從 Pregel 執行引擎發出原始圖執行事件（如 `values`、`updates`、`messages`、`custom`、`checkpoints`、`tasks`、`debug` 與 JS 的 `tools`），並支援以 `version="v2"` 輸出統一的 `StreamPart` 格式；高層的 **Event Streaming（事件串流 API，LangGraph v1.2+ 推薦）** 則透過 `stream_events(..., version="v3")` / `streamEvents(..., { version: "v3" })` 將底層事件正規化為 `ProtocolEvent`，經由 `StreamTransformer` 轉換後提供型別化的投影（如 `stream.messages`、`stream.values`、`stream.subgraphs`、`stream.output`、`stream.extensions`）。關鍵詞：LangGraph 串流、串流模式、事件串流
- [[concepts/langgraph-subgraphs-and-fault-tolerance]] — LangGraph 支援將編譯後的圖作為**子圖（Subgraphs）**嵌入父圖，提供「在節點內呼叫子圖（不共享狀態鍵）」與「將子圖直接加入為節點（共享狀態鍵）」兩種通訊模式，並透過 `compile(checkpointer=None | True | False)` 控制子圖為單次呼叫隔離（Per-invocation）、跨呼叫累積（Per-thread）或無狀態（Stateless）。關鍵詞：子圖與容錯機制、Subgraphs、Fault Tolerance

- [[guides/langgraph-deployment-and-studio]] — LangGraph 應用程式由一個或多個圖（Graphs）、設定檔 `langgraph.json`、依賴管理檔（`requirements.txt`、`pyproject.toml` 或 `package.json`）與 `.env` 環境變數檔組成。關鍵詞：LangGraph 專案結構、本地開發伺服器、LangSmith Studio

## 比較（comparisons）
- [[comparisons/agent-sdk-python-vs-typescript]] — 本頁比較 Claude Agent SDK 在 Python（`claude-agent-sdk`）與 TypeScript（`@anthropic-ai/claude-agent-sdk`）兩個官方語言版本間的架構設計、命名慣例、核心 API、多輪對話與預熱機制、In-Process MCP 工具定義、Hook 攔截事件、沙盒預設行為及錯誤處理差異。關鍵詞：Agent SDK Python 與 TypeScript 比較、`claude-agent-sdk` vs `@anthropic-ai/claude-agent-sdk`、Python 與 TypeScript SDK 差異對照
- [[comparisons/checkpointing-and-persistence-comparison]] — 四個框架皆支援執行狀態的持久化與回溯，但設計層級與儲存標的截然不同：Claude Agent SDK 分離了「對話工作階段 JSONL 轉錄檔（Session Storage）」與「磁碟檔案系統快照（File Checkpointing）」；LangGraph 則在圖執行的每個 Super-step 邊界透過 `BaseCheckpointSaver` 將完整圖狀態（State Channels、待執行節點與中斷狀態）寫入資料庫；LangChain 直接建構於 LangGraph 的 `checkpointer`（短期對話記憶）與 `BaseStore`（跨執行緒長期記憶）之上；Deep Agents 則進一步結合 LangGraph 持久化與可插拔的檔案系統後端（`BackendProtocol`）。關鍵詞：跨框架檢查點與持久化比較、Checkpointing 比較、狀態存檔與回溯比較
- [[comparisons/deepagents-vs-other-frameworks]] — Deep Agents 與 Claude Agent SDK 皆為用於建構自訂代理的 agent harness，但在執行環境架構、多租戶（multi-tenancy）支援、部署模式與模型供應商耦合度上採取了不同取捨。關鍵詞：Deep Agents 與其他框架比較、Deep Agents vs Claude Agent SDK、Agent Harness 比較
- [[comparisons/human-in-the-loop-and-permissions-comparison]] — 為了控制代理行為並攔截高風險操作，四個框架分別採用了「子程序 IPC 回呼與 Hook 管線（Claude Agent SDK）」與「基於圖檢查點的持久化中斷 `interrupt()` 與洋蔥式 Middleware（LangGraph / LangChain / Deep Agents）」兩大技術路線。關鍵詞：跨框架人工審批與權限及攔截器比較、HITL 比較、Permissions vs interrupt_on vs interrupt()
- [[comparisons/langchain-ecosystem-python-vs-typescript]] — LangChain、LangGraph 與 Deep Agents 皆同步提供 Python 與 TypeScript/JavaScript（Node.js 20+）SDK。關鍵詞：LangChain 生態系 Python 與 TypeScript 差異比較、Python vs JS/TS 對照表、create_agent vs createAgent
- [[comparisons/memory-skills-and-context-engineering-comparison]] — 面對長對話與龐大工具集帶來的上下文視窗（Context Window）限制，四個框架分別發展出專案記憶檔（`CLAUDE.md` vs `AGENTS.md`）、漸進式揭露技能（`SKILL.md`）、按需工具載入（Tool Search vs `LLMToolSelectorMiddleware`）以及自動上下文壓縮（Auto-Compaction vs `SummarizationMiddleware` 與大型工具輸出卸載）。關鍵詞：跨框架記憶與技能及上下文工程比較、Memory 比較、Skills 比較
- [[comparisons/subagents-and-multi-agent-comparison]] — 四個框架都提供將複雜任務拆解給多個代理（Subagents / Multi-Agent）的機制，以實現上下文隔離（Context Isolation）與職責分工：Claude Agent SDK 透過 `agents` 選項定義 `AgentDefinition` 並由內建 `Agent`（舊稱 `Task`）工具派發；Deep Agents 內建 `SubAgentMiddleware` 與 `AsyncSubAgentMiddleware`，支援宣告式 `SubAgent`、預編譯圖 `CompiledSubAgent`、遠端非同步子代理與動態建立子代理；LangChain 歸納出 Subagents、Handoffs、Skills 與 Router 四大多代理模式；LangGraph 則提供底層的 Subgraphs、`Command` 跨圖跳轉與 `Send` 平行 Map-Reduce 原語。關鍵詞：跨框架子代理與多代理比較、Subagents 比較、Multi-Agent 架構對照
